# 55. Notification Schema

Schema

```text id="notification-schema"
notification
```

The Notification schema manages all platform communications with users and external systems.

Notifications SHALL be event-driven and independently scalable.

Supported channels include:

- In-App
- Email
- Telegram
- WhatsApp
- SMS (Future)
- Push Notifications (Future)
- Webhooks

---

# 59. Database Governance

---

## Versioning

Every schema change SHALL occur through version-controlled migrations.

Manual schema modification in production SHALL NOT be permitted.

---

## Data Ownership

Each bounded context SHALL own its schema.

Cross-domain writes SHALL occur only through Application Services.

---

## Archiving

Large historical datasets SHALL support archival.

Examples

- Tick History
- Logs
- Audit Events
- Event Store
- Analytics Snapshots

---

## Partitioning

The following tables SHOULD support partitioning:

- market_ticks
- market_candles
- domain_events
- audit_events
- execution_orders
- execution_positions
- daily_statistics

Partition strategy SHALL be time-based.

---

## Backup Strategy

Backup categories:

- Full Backup
- Incremental Backup
- Point-in-Time Recovery (PITR)

Backups SHALL be verified before retention.

---

## Retention Policy

| Data Type | Retention |
|------------|-----------|
| Audit Events | Permanent |
| Domain Events | Permanent |
| Orders | Permanent |
| Positions | Permanent |
| Deals | Permanent |
| Market Ticks | Configurable |
| Notifications | 365 Days |
| Logs | Configurable |
