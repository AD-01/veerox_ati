# 43. Execution Schema

Schema

```text id="execution-schema"
execution
```

The Execution Domain is responsible for the complete lifecycle of every trading operation.

**Important Principle**

The Execution Domain SHALL NOT decide **whether** to trade.

It SHALL only execute approved decisions received from the Decision and Policy Domains.

The Execution schema SHALL maintain the authoritative history of:

- Execution Requests
- Orders
- Deals
- Positions
- Trade Lifecycle
- MT5 Synchronization
- Execution Performance

```text id="trade-lifecycle"

        │
        ▼
Order Submitted
        │
        ▼
Order Accepted
        │
        ▼
Deal Executed
        │
        ▼
Position Opened
        │
        ▼
Position Modified
        │
        ▼
Position Closed
        │
        ▼

```

Every state transition SHALL generate a domain event.

# 48. Design Rules

The Execution schema SHALL satisfy the following constraints:

- Every Position SHALL originate from exactly one Execution Request.
- Every Execution Request SHALL reference one approved Decision.
- Broker identifiers SHALL remain immutable.
- Position modifications SHALL preserve complete history.
- Synchronization SHALL never overwrite broker history.
- Reconciliation SHALL preserve all detected discrepancies until resolved.
- Execution metrics SHALL support operational analytics without affecting transactional consistency.
